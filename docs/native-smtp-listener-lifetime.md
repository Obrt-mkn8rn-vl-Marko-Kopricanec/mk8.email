# Native SMTP bind and shutdown

`Smtp.ListenAddress` selects one literal IPv4 or IPv6 address for all enabled SMTP, submission and implicit-TLS listeners. The default remains `0.0.0.0`, the previous IPv4 wildcard bind. Use `127.0.0.1` for an IPv4 loopback-only listener. DNS names and address:port strings are refused by presentation configuration validation; ports remain separate existing settings. An IPv6 address is not a promise of dual-stack listening. IMAP, POP3, ManageSieve and HTTP bindings are unchanged.

Native mail listeners remain owned by Email, not an HTTP reverse proxy. This setting does not allocate an address/port, trust a proxy, change TLS or authentication policy, enable a protocol or issue a certificate.

The SMTP service retains actual accepted session tasks. When an accept loop ends or a bind fails, it closes admission, cancels sibling listeners and joins admitted sessions before its execution finishes. Only already-completed-successfully sessions leave the active inventory early. Individual connection failures keep the existing log-and-close behavior; listener/shutdown faults are retained through aggregate completion. Inherited .NET 10 `StartAsync` schedules background execution; its return alone is not proof of a bound listener or readiness.

The first `StopAsync` starts shared shutdown. Subsequent and concurrent calls join that same body and its faults, even if cancellation callbacks fail. Each caller's cancellation token bounds only its own wait; it does not abandon the service's shutdown body. Ownership uses the actual base execution task, not an override of the public inspection property. A successfully completed stop means listener and session work has settled. A cancelled wait or other failure is not permission to dispose dependencies under still-active execution. `Dispose` is not an asynchronous join, and noncooperative dependencies are not guaranteed to terminate within a hard deadline. Standard hosted-service usage remains start once, stop, then dispose; no restart-in-place contract is added.

The bounded development controls start the real service on IPv4 loopback: two journal-held greetings, cancelled/concurrent stop waits, injected assertion cleanup, a cancellation-callback fault held inside the actual recipient call, greeting/QUIT, a sibling port collision, disabled listeners and a subclass whose inspection property deliberately hides the actual execution task. Their application/journal dependencies are deliberate controls, not production authentication, recipient/storage/delivery proof. Address validation also covers IPv6 literal admission, not an IPv6 network execution certificate.

These source controls do not establish full host/environment startup, public TLS/DNS, actual Sava/default verified-HTTPS interoperability, client compatibility, physical durability, clean full-suite validation, root cause, stability/SLA or deployment readiness. Historical failed/unknown evidence and all owner/review/artifact/configuration/certificate/installation/health/production gates remain controlling.
